# 阶段任务对照检查清单

本文档用于把《深潮回收站》的开发阶段压缩成一份可以直接对照勾选的检查清单。

使用方式：

1. 每开始一个阶段前，先看“本阶段目标”。
2. 开发过程中按“必须完成任务”逐项对照。
3. 开发结束后按“阶段完成标志”判断能否进入下一阶段。
4. 如果某阶段没有通过，不要跳到后面阶段堆功能。

---

## 总主线

项目必须始终围绕以下主线推进：

1. 先把工程跑起来。
2. 再让玩家能在场景里行动。
3. 再加入氧气和采集，形成压力与收益。
4. 再打通返航结算，形成闭环。
5. 再加入升级、危险、海域推进和完成度打磨。

一句话总结：

`先能跑，再能玩，再更完整，再更适合展示。`

## P0 工程基础确认

### 本阶段目标

建立一个可编译、可启动、可刷新的 Qt 图形化工程，作为后续所有功能的宿主。

### 必须完成任务

- [ ] 新建正式项目工程，不再只停留在环境测试样例。
- [ ] 配置 `C++17 + Qt Widgets + QPainter + QTimer` 基础技术栈。
- [ ] 建立主窗口 `GameWindow`。
- [ ] 建立基础场景 `GameScene`。
- [ ] 接入统一刷新入口，确保场景持续更新。
- [ ] 确保键盘输入可以进入场景对象。
- [ ] 建立资源目录约定：
  - [ ] `assets/images/`
  - [ ] `assets/sounds/`
  - [ ] `assets/maps/`
- [ ] 建立最基础的启动日志、资源日志、输入日志。
- [ ] 给出最小可见画面，哪怕只是占位背景和占位潜水器。
- [ ] 记录启动排障说明，方便后续复用。
- [ ] 固定一套稳定构建方式，避免环境问题反复出现。

### 阶段完成标志

- [ ] 工程能成功配置。
- [ ] 工程能成功编译。
- [ ] 程序启动后会显示主窗口。
- [ ] 场景会持续刷新，不是静态假界面。
- [ ] 控制台能看到输入日志。
- [ ] 资源目录检查通过。

### 当前阶段产物

- [ ] `CMakeLists.txt`
- [ ] `src/main.cpp`
- [ ] `src/gamewindow.*`
- [ ] `src/gamescene.*`
- [ ] `src/projectpaths.*`
- [ ] 构建脚本
- [ ] P0 排障说明

## P1 玩家移动

### 本阶段目标

让玩家真正能控制一个对象在海底场景中移动，并具备稳定的基础手感。

### 必须完成任务

- [ ] 创建 `Player` 类。
- [ ] 设计玩家的基础字段：
  - [ ] 位置
  - [ ] 速度
  - [ ] 朝向
  - [ ] 状态
- [ ] 把按键输入转换为持续输入状态，而不是只响应单次按下。
- [ ] 实现上下左右移动。
- [ ] 使用 `dt` 更新位置，不在绘制函数里改逻辑。
- [ ] 绘制玩家本体或玩家占位图。
- [ ] 处理按键按下和松开后的状态变化。
- [ ] 记录移动调试信息，便于后续看手感。
- [ ] 固定玩家初始出生位置。

### 阶段完成标志

- [ ] `WASD` 或方向键能控制玩家移动。
- [ ] 松开按键后能正常停止。
- [ ] 长按不会卡顿或漂移。
- [ ] 同时按两个方向键时行为可预测。
- [ ] 玩家进入场景后总能出现在正确位置。

### 当前阶段产物

- [ ] `Player` 基础类
- [ ] 玩家输入状态记录
- [ ] 玩家位置更新逻辑
- [ ] 玩家基础绘制表现

## P2 碰撞与边界

### 本阶段目标

建立地图边界和障碍规则，让场景从“背景图”变成真正有空间限制的海域。

### 必须完成任务

- [ ] 明确世界坐标和屏幕坐标关系。
- [ ] 定义地图边界。
- [ ] 添加若干静态障碍物。
- [ ] 实现基础碰撞检测，推荐先用 AABB。
- [ ] 处理玩家与障碍、边界的碰撞修正。
- [ ] 把碰撞更新从移动逻辑里理清，不要写成混乱的 if 堆叠。
- [ ] 预留后续资源点、危险区的坐标体系。
- [ ] 最好有可选的碰撞盒调试显示。

### 阶段完成标志

- [ ] 玩家不能穿墙。
- [ ] 玩家不能移出地图。
- [ ] 贴边移动时不会严重抖动。
- [ ] 斜向撞角时不会明显瞬移。

### 当前阶段产物

- [ ] 地图边界逻辑
- [ ] 障碍物数据
- [ ] 玩家碰撞修正逻辑
- [ ] 碰撞调试手段

## P3 氧气系统

### 本阶段目标

把海底探索变成“有限时间内做决策”的游戏，而不是无限制地游动和收集。

### 必须完成任务

- [ ] 给玩家接入氧气属性：
  - [ ] `oxygen`
  - [ ] `maxOxygen`
- [ ] 设计基础氧气消耗。
- [ ] 设计深度附加消耗或深度风险机制。
- [ ] 把氧气变化接入每帧更新。
- [ ] 增加氧气 HUD 显示。
- [ ] 增加低氧预警颜色或提示。
- [ ] 定义氧气归零后的规则：
  - [ ] 扣血
  - [ ] 失败
  - [ ] 倒计时
  - [ ] 三选一或固定组合
- [ ] 记录氧气变化来源，便于后期调参。

### 阶段完成标志

- [ ] 氧气会随时间下降。
- [ ] 深度变化会影响氧气压力或风险提示。
- [ ] 氧气低时能明显看见预警。
- [ ] 氧气归零后有明确反馈，不会静默失效。

### 当前阶段产物

- [ ] 氧气数值字段
- [ ] 氧气消耗逻辑
- [ ] 氧气 HUD
- [ ] 低氧预警机制

## P4 采集与背包

### 本阶段目标

让玩家能真正回收资源，并把“探索”转化为“收益”。

### 必须完成任务

- [ ] 创建 `ResourceItem` 类。
- [ ] 建立资源分类，至少覆盖参考方案中的核心类型：
  - [ ] 荧团浮体
  - [ ] 壳晶矿
  - [ ] 冷凝胶
  - [ ] 旧时代零件
- [ ] 区分瞬时拾取资源和持续采集资源。
- [ ] 实现玩家与资源的靠近判定。
- [ ] 增加交互提示。
- [ ] 实现采集行为和采集进度。
- [ ] 实现背包或库存的本次出航记录。
- [ ] 增加背包容量或重量限制。
- [ ] 完成采集后从场景里移除资源。
- [ ] 处理采集中断逻辑：
  - [ ] 移动中断
  - [ ] 受击中断
  - [ ] 离开范围中断

### 阶段完成标志

- [ ] 玩家能采集资源。
- [ ] 资源进入背包后数量正确。
- [ ] 背包满时不能继续无脑采集。
- [ ] 同一资源不会被重复结算。
- [ ] 采集中断后状态能正确恢复。

### 当前阶段产物

- [ ] 资源对象系统
- [ ] 交互提示
- [ ] 背包基础结构
- [ ] 采集进度和完成逻辑

## P5 返航结算

### 本阶段目标

首次打通完整的玩法闭环：`出航 -> 采集 -> 返航 -> 结算`。

### 必须完成任务

- [ ] 定义返航区域或海面安全区。
- [ ] 明确返航成功判定。
- [ ] 汇总本次出航采集数据。
- [ ] 设计结算界面。
- [ ] 将可售卖资源转换为金币。
- [ ] 将可保留材料写入长期库存。
- [ ] 清理本次出航的临时状态。
- [ ] 保留长期状态：
  - [ ] 金币
  - [ ] 图鉴
  - [ ] 升级数据
  - [ ] 海域解锁状态
- [ ] 如果有失败返航规则，也要明确惩罚逻辑。

### 阶段完成标志

- [ ] 玩家返航后会进入结算界面。
- [ ] 结算内容和背包内容一致。
- [ ] 金币变化正确。
- [ ] 再次出航时临时背包会清空。
- [ ] 长期资产不会丢失。

### 当前阶段产物

- [ ] 返航判定
- [ ] 结算数据结构
- [ ] 结算界面
- [ ] 金币与材料流转逻辑

## P6 升级系统

### 本阶段目标

让玩家返航后的收益能转化为下一次出航的成长反馈。

### 必须完成任务

- [ ] 建立升级界面或基地升级入口。
- [ ] 定义升级项，至少建议包括：
  - [ ] 压缩气瓶
  - [ ] 推进器
  - [ ] 货舱模块
  - [ ] 回收机械臂
  - [ ] 耐压壳体
- [ ] 为每个升级项定义：
  - [ ] 等级上限
  - [ ] 金币消耗
  - [ ] 材料消耗
  - [ ] 升级效果
- [ ] 实现升级购买逻辑。
- [ ] 把升级效果真正作用到玩家或系统参数上。
- [ ] 增加金币不足、材料不足的提示。
- [ ] 再次出航时，正确加载升级后的属性。

### 阶段完成标志

- [ ] 升级能成功购买。
- [ ] 升级后属性真的变化，不只是文案变化。
- [ ] 到达上限后不能继续升级。
- [ ] 退出再进入后升级状态仍然存在。

### 当前阶段产物

- [ ] 升级界面
- [ ] 升级规则表
- [ ] 属性刷新逻辑
- [ ] 升级长期保存逻辑

## P7 危险单位与环境机制

### 本阶段目标

让玩家面对主动风险，而不只是单纯采集。

### 必须完成任务

- [ ] 添加至少一种危险生物。
- [ ] 添加至少一种危险地形。
- [ ] 定义危险单位的基础行为：
  - [ ] 待机
  - [ ] 巡逻
  - [ ] 发现玩家
  - [ ] 攻击
  - [ ] 冷却
- [ ] 定义环境危险效果：
  - [ ] 热泉
  - [ ] 水流
  - [ ] 黑暗区
  - [ ] 至少实现一种
- [ ] 实现玩家受击反馈。
- [ ] 明确伤害类型：
  - [ ] 扣血
  - [ ] 扣氧
  - [ ] 击退
  - [ ] 失控
- [ ] 让危险在画面上可识别，而不是纯数据暗算。

### 阶段完成标志

- [ ] 危险生物或危险地形能稳定触发效果。
- [ ] 玩家能观察、规避并理解风险来源。
- [ ] 受击后不会把返航、采集、结算状态打乱。

### 当前阶段产物

- [ ] 危险单位基础逻辑
- [ ] 危险地形逻辑
- [ ] 玩家受击反馈
- [ ] 风险提示效果

## P8 海域推进与解锁

### 本阶段目标

建立中期目标和层次感，让玩家知道“为什么还要继续往下做”。

### 必须完成任务

- [ ] 至少制作第二海域。
- [ ] 明确每片海域的差异：
  - [ ] 深度范围
  - [ ] 主要资源
  - [ ] 主要危险
  - [ ] 视觉色调
- [ ] 设计海域解锁条件。
- [ ] 在基地界面提示还差哪些解锁条件。
- [ ] 确保新海域不仅换背景，也换风险和收益结构。
- [ ] 让旧海域仍有存在价值，不要完全作废。

### 阶段完成标志

- [ ] 未满足条件时不能进入新海域。
- [ ] 满足条件后能成功解锁。
- [ ] 新旧海域在资源、风险或视觉上有明显差异。
- [ ] 海域解锁状态能够长期保存。

### 当前阶段产物

- [ ] 第二海域地图与配置
- [ ] 海域解锁逻辑
- [ ] 差异化资源与危险布局
- [ ] 基地界面解锁提示

## 跨阶段必查项

无论当前做到哪个阶段，每次较大改动后都至少检查：

- [ ] 程序还能启动。
- [ ] 主窗口还能显示。
- [ ] 基础场景还能刷新。
- [ ] 玩家输入没有失效。
- [ ] 新功能没有破坏旧功能。

## 建议的实际检查顺序

每次准备进入下一阶段前，按这个顺序检查：

1. [ ] 先确认当前阶段主路径已经通了。
2. [ ] 再确认本阶段没有高优先级崩溃问题。
3. [ ] 再确认旧功能没有被回归破坏。
4. [ ] 再确认本阶段产物已经写进文档。
5. [ ] 最后再进入下一阶段。
