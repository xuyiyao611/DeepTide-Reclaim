# 深潮回收站文档说明

本文档目录以 `海底采集游戏原创复刻方案.md` 为概念总稿，负责把方案落成可执行、可测试、可录制、可提交的一整套配套文档。

这套文档的中心不是单个功能说明，而是围绕 `下潜探索 -> 采集资源 -> 氧气受限 -> 返航结算 -> 升级成长 -> 解锁更深海域` 这条主线展开。

## 文档使用目标

1. 让项目在编码前先有统一术语、统一阶段编号、统一资源命名。
2. 让每个阶段都能回答为什么现在做它、做完后如何验证它。
3. 让架构、测试、视频和报告材料互相对应，而不是各写各的。
4. 让最终提交时只需要按文档顺序检查，而不是临时回忆。
5. 让项目保持原创表达，同时保留海底采集题材最关键的玩法闭环。

## 与参考方案的关系

参考文件：`海底采集游戏原创复刻方案.md`。
当前目录下的其他文件负责把该方案进一步细化成开发流程、架构边界、测试方法、视频话术和交付检查。
因此，任何新增文档内容都应围绕参考方案中的世界观、资源体系、海域命名和升级逻辑扩展，而不是另起一套设定。

## 项目一句话概览

《深潮回收站》是一个基于 `C++ + Qt Widgets` 的 2D 海底采集与成长类游戏原型。
玩家扮演海面回收站潜航员，在有限氧气下进入深海回收资源、躲避危险、返航结算，再利用收益升级装备并挑战更深海域。

## 原创表达边界

- 保留题材循环，不复制原游戏名称、角色、美术、文案和 UI 布局。
- 使用荧团浮体、壳晶矿、冷凝胶、旧时代零件等原创资源命名。
- 使用近岸浅层回收带、断层采样区、热泉回路区、冷流峡谷区等原创海域命名。
- 用海面回收站、深度许可证、回收机械臂等原创系统表达替代原作说法。
- 把世界观压缩到课程作业需要的最小可解释规模，避免写成大型叙事 RPG。

## 资源体系总览


### 荧团浮体

定位：浅层常见售卖资源
采集方式：靠近即可回收
设计作用：前期金币来源，强调新手正反馈。
文档要求：荧团浮体 的出现位置、价值区间、图鉴描述和视频讲解口径应保持一致。
测试提示：需要验证 荧团浮体 的获取、入包、结算或保留逻辑不会和其他资源混淆。

### 壳晶矿

定位：附着在岩壁上的升级材料
采集方式：需要短暂停留采集
设计作用：用于引导玩家在障碍附近承担风险。
文档要求：壳晶矿 的出现位置、价值区间、图鉴描述和视频讲解口径应保持一致。
测试提示：需要验证 壳晶矿 的获取、入包、结算或保留逻辑不会和其他资源混淆。

### 冷凝胶

定位：中层稀有材料
采集方式：多分布在冷流和热泉交界
设计作用：适合驱动氧气和耐压升级。
文档要求：冷凝胶 的出现位置、价值区间、图鉴描述和视频讲解口径应保持一致。
测试提示：需要验证 冷凝胶 的获取、入包、结算或保留逻辑不会和其他资源混淆。

### 旧时代零件

定位：深层高价值材料
采集方式：通常伴随危险或高压区域
设计作用：用于高阶升级和海域解锁。
文档要求：旧时代零件 的出现位置、价值区间、图鉴描述和视频讲解口径应保持一致。

## 海域体系总览


### 近岸浅层回收带

深度范围：0m - 120m
阶段定位：新手教学海域
主要资源：荧团浮体、少量壳晶矿
设计说明：风险低，适合熟悉移动、采集和返航。
演示价值：视频里要让老师一眼看出 近岸浅层回收带 和其他海域的差异，不只是背景颜色变化。

### 断层采样区

深度范围：120m - 350m
阶段定位：中期主力海域
主要资源：壳晶矿、冷凝胶
设计说明：障碍增多，返航路线开始重要。
演示价值：视频里要让老师一眼看出 断层采样区 和其他海域的差异，不只是背景颜色变化。

### 热泉回路区

深度范围：350m - 700m
阶段定位：高压高收益海域
主要资源：冷凝胶、旧时代零件
设计说明：热泉和危险单位会迫使玩家判断停留时机。
演示价值：视频里要让老师一眼看出 热泉回路区 和其他海域的差异，不只是背景颜色变化。

### 冷流峡谷区

深度范围：700m - 1200m
阶段定位：最终挑战海域
主要资源：高稀有度旧时代零件
设计说明：适合作为终局解锁与完整图鉴目标。
演示价值：视频里要让老师一眼看出 冷流峡谷区 和其他海域的差异，不只是背景颜色变化。

## 升级体系总览


### 压缩气瓶

效果：提升氧气上限
设计价值：直接拉长探索时间
实现注意：应作为最直观的成长反馈之一。
测试重点：升级前后要能在数值和体验上都验证 压缩气瓶 的真实效果。

效果：提升移动速度
设计价值：改善返航容错和赶路效率

### 货舱模块

测试重点：升级前后要能在数值和体验上都验证 货舱模块 的真实效果。

### 回收机械臂

## 推荐操作说明

- `W / 上方向键`：上浮。用于接近海面返航或规避地形。
- `S / 下方向键`：下潜。用于前往更深区域。
- `A / 左方向键`：左移。用于绕过障碍和危险。
- `D / 右方向键`：右移。用于探索横向路径。
- `E / 空格`：交互或采集。用于回收资源、确认提示。
- `Esc`：暂停或返回。用于中止操作和进入菜单。

## 项目推进总览


### P0 工程基础确认

阶段目标：建立可编译、可启动、可刷新的 Qt 图形化工程，让后续所有系统都有稳定宿主。
为什么重要：如果这一阶段不稳定，后续任何玩法功能都会在窗口、资源路径或主循环问题上反复返工。
核心关注：项目骨架、主窗口、资源路径、QTimer 刷新、输入事件基础
阶段产物：
- 可启动主程序
- 空白测试场景
- 稳定定时刷新
- 输入日志输出
进入下一阶段的条件：至少完成一轮自测，并把关键结论写回阶段文档。

### P1 玩家移动

阶段目标：建立潜航员在水下移动的基础手感，让玩家真正能控制一个对象探索海域。
为什么重要：移动是所有系统的依附对象，没有玩家控制就无法讲采集、氧气、返航和危险。
核心关注：Player 类、输入状态记录、速度和位置更新、角色绘制、基础手感
阶段产物：
- Player 类初版
- 上下左右移动
- 角色占位图
- 位置更新日志
进入下一阶段的条件：至少完成一轮自测，并把关键结论写回阶段文档。

### P2 碰撞与边界

阶段目标：建立海域边界和障碍规则，让玩家不能穿墙、不能越界，并开始形成路线选择。
为什么重要：没有边界和障碍，地图只是一张背景图，海域空间不会产生设计意义。
核心关注：地图坐标系、边界框、障碍物、AABB 碰撞、分轴修正
阶段产物：
- 地图边界
- 静态障碍布局
- 玩家碰撞修正
- 测试障碍区
进入下一阶段的条件：至少完成一轮自测，并把关键结论写回阶段文档。

### P3 氧气系统

阶段目标：把时间压力和深度压力接入核心循环，迫使玩家在探索和返航之间做决策。
为什么重要：氧气系统是海底采集题材区别于普通收集游戏的第一核心约束。
核心关注：maxOxygen、oxygen、基础消耗、深度附加、HUD 预警
阶段产物：
- 氧气属性
- 氧气条 HUD
- 低氧预警
- 归零反馈
进入下一阶段的条件：至少完成一轮自测，并把关键结论写回阶段文档。

### P4 采集与背包

阶段目标：建立资源对象、交互提示、采集耗时和容量限制，让海底探索真正产生回报。
为什么重要：如果没有采集与背包，玩家只是移动和耗氧，主题无法成立。
核心关注：资源对象、交互范围、采集进度、背包容量、资源入包
阶段产物：

## 构建与运行原则

- 固定工程编码和资源目录规则，避免因为路径和乱码产生无意义问题。
- 所有实时游戏逻辑统一通过 QTimer 触发的更新入口驱动。
- 不要在绘制函数里偷改逻辑状态。
- 不要为了赶进度跳过阶段自测，否则后期返工成本更高。
- 所有新功能都应首先接入最小日志，保证可观察。
- 演示版可以单独调参数，但不能和正式逻辑混在一起且无记录。

## 测试原则

- 先测单功能，再测联动，再测完整出航闭环。
- 每次改动至少回归启动、移动、碰撞、氧气、采集、返航、结算七个核心点。
- 任何一个阶段如果会影响存档、升级或海域解锁，必须额外做跨阶段回归。
- 视频录制前的演示检查，本质上是最终回归测试。
- 测试记录不是装饰，要能反映出哪些问题修过、哪些问题被规避。
