# 执行计划与测试

## 1. 文档定位

本文档负责把 `项目工作流程.md` 中的阶段目标落成“执行内容 + 测试动作 + 通过标准 + 回归检查”。

如果你不知道下一步应该改什么，看“执行内容”。

如果你不知道改完后怎么测，看“测试动作”。

如果你不知道当前算不算做完，看“通过标准”。

## 2. 总执行表

| 阶段 | 执行重点 | 测试重点 | 通过标准 |
|---|---|---|---|
| P0 | 工程基础确认 | 启动、渲染、输入 | 工程可稳定运行 |
| P1 | 玩家移动 | 键盘输入、帧更新 | 角色移动自然且稳定 |
| P2 | 碰撞与边界 | 穿墙、越界、滑动 | 地图规则成立 |
| P3 | 氧气系统 | 递减、预警、归零 | 氧气压力成立 |
| P4 | 采集与背包 | 拾取、背包满、中断 | 采集闭环成立 |
| P5 | 返航结算 | 安全返航、收益计算 | 核心玩法闭环成立 |
| P6 | 升级系统 | 购买、数值变化、上限 | 成长反馈成立 |
| P7 | 危险单位 | 伤害、状态、规避 | 风险机制成立 |
| P8 | 海域推进 | 解锁、差异化、目标感 | 中期推进成立 |
| P9 | 完成度打磨 | 存档、图鉴、界面 | 演示质量达标 |
| P10 | 提交物验证 | 视频、报告、仓库 | 可提交状态成立 |

## 3. P0 工程基础确认

### 执行内容

1. 新建 Qt 工程。
2. 创建主窗口和基础场景。
3. 接入 `QTimer` 刷新。
4. 验证资源目录可读。

### 测试动作

- 启动程序，观察是否正常显示窗口。
- 连续启动 5 次，确认没有随机崩溃。
- 按下键盘，确认可以触发输入事件日志或测试标志。

### 通过标准

- 无编译错误。
- 无启动崩溃。
- 可以稳定看到场景刷新。

### 回归检查

- 修改工程设置后，再次确认资源路径仍然有效。

## 4. P1 玩家移动

### 执行内容

1. 创建 `Player` 类。
2. 接入方向键或 `WASD`。
3. 每帧更新位置。
4. 绘制角色。

### 测试动作

- 依次测试上、下、左、右移动。
- 同时按两个方向键，观察对角移动行为是否符合预期。
- 长按按键 10 秒，观察是否卡顿。

### 通过标准

- 玩家能稳定移动。
- 松开按键能正确停止。
- 移动没有明显抖动和拖影错位。

### 回归检查

- 再次启动程序，玩家初始位置正确。

## 5. P2 碰撞与边界

### 执行内容

1. 添加地图边界。
2. 放置障碍物。
3. 实现 AABB 碰撞。
4. 处理玩家碰撞后的修正逻辑。

### 测试动作

- 从四个方向撞击同一障碍。
- 贴边连续移动，观察是否穿墙。
- 冲向地图边缘，观察是否越界。

### 通过标准

- 玩家不能穿过障碍。
- 玩家不能移出地图。
- 碰撞后位置修正不应突然跳跃。

### 回归检查

- 碰撞加入后，基础移动手感未被明显破坏。

## 6. P3 氧气系统

### 执行内容

1. 增加氧气属性。
2. 设计基础氧气消耗。
3. 设计深度附加消耗。
4. 增加氧气 UI。
5. 增加低氧警告。

### 测试动作

- 静止等待，观察氧气是否持续下降。
- 下潜到更深位置，比较下降速度。
- 把氧气调到低值，观察颜色和警告是否生效。
- 让氧气归零，观察失败或扣血逻辑。

### 通过标准

- 氧气会随时间正确消耗。
- 深度会影响氧气消耗或风险提示。
- 氧气为零后游戏有明确反馈。

### 回归检查

- 引入氧气后，玩家移动和渲染仍稳定。

## 7. P4 采集与背包

### 执行内容

1. 创建资源对象。
2. 实现靠近判定。
3. 实现采集动作和进度条。
4. 实现背包容量检查。
5. 采集完成后移除场景对象。

### 测试动作

- 靠近资源时是否出现交互提示。
- 采集完成后是否进入背包。
- 采集中移动是否中断。
- 背包满时是否禁止继续采集。

### 通过标准

- 资源可稳定加入背包。
- 不会重复采集同一资源。
- 背包限制生效。

### 回归检查

- 采集系统加入后，氧气逻辑和移动碰撞仍正确。

## 8. P5 返航结算

### 执行内容

1. 定义返航点。
2. 实现返航成功判定。
3. 汇总本次资源。
4. 生成结算界面。
5. 把可卖资源转换为金币。

### 测试动作

- 不采集资源直接返航。
- 采集少量资源后返航。
- 采集多类资源后返航。
- 在低氧时惊险返航，观察是否仍能正确结算。

### 通过标准

- 返航后一定进入结算。
- 结算数据和背包内容一致。
- 金币变化正确。

### 回归检查

- 返航完成后再次出航，氧气、位置和背包初始化正确。

## 9. P6 升级系统

### 执行内容

1. 建立升级界面。
2. 设计升级项和等级上限。
3. 实现金币或材料消耗。
4. 把升级效果作用到玩家属性上。

### 测试动作

- 用足够金币购买升级。
- 金币不足时尝试购买。
- 升级后再次出航，观察属性变化。
- 连续升级到上限，观察是否会超限。

### 通过标准

- 升级能正确扣费。
- 升级后属性可见且稳定生效。
- 到达上限后不再允许升级。

### 回归检查

- 升级数据不会在返回主界面或再次出航时丢失。

## 10. P7 危险单位与环境机制

### 执行内容

1. 添加至少 1 种危险生物。
2. 添加至少 1 种危险地形。
3. 增加受击反馈和状态效果。

### 测试动作

- 与危险生物接触，观察扣血或扣氧行为。
- 进入热泉区，观察持续伤害。
- 反复碰撞危险物，观察是否有无敌帧或过量触发问题。

### 通过标准

- 危险单位有明确存在意义。
- 玩家可观察、可规避、可受罚。

### 回归检查

- 危险机制加入后，结算和返航逻辑不应异常。

## 11. P8 海域推进

### 执行内容

1. 制作第二海域。
2. 设置海域解锁条件。
3. 增加新资源或新危险。

### 测试动作

- 未满足条件时尝试进入新海域。
- 满足条件后再次进入。
- 对比新旧海域的资源、难度和视觉差异。

### 通过标准

- 海域解锁逻辑正确。
- 新海域确实提供新的目标和风险。

### 回归检查

- 第一海域仍然能正常游玩和返航。

## 12. P9 完成度打磨

### 执行内容

1. 增加存档。
2. 增加图鉴。
3. 打磨 HUD、菜单和结算界面。
4. 补音效和反馈动画。

### 测试动作

- 退出后重进，确认存档存在。
- 新见到的资源是否记录进图鉴。
- 多次切换界面，确认没有卡死和错位。

### 通过标准

- 项目具备基本可展示完成度。
- UI 一致性明显提升。

### 回归检查

- 存档不会破坏升级和背包数据。

## 13. P10 提交物验证

### 执行内容

1. 整理仓库目录和说明。
2. 对照作业要求检查提交物。
3. 准备视频讲解脚本。
4. 准备实验报告提纲。

### 测试动作

- 用演示账号或空环境重新跑一遍项目。
- 按视频脚本完整讲一遍，计时是否在 5 到 8 分钟内。
- 核对仓库公开、提交次数、说明文档和演示流程。

### 通过标准

- 代码、文档、视频素材都已就绪。
- 能无卡壳地完整演示一遍。

### 回归检查

- 录视频前重新测试核心闭环，防止最后一刻出问题。

## 14. 核心回归测试清单

每完成一个阶段，至少回归以下内容：

1. 程序能正常启动。
2. 玩家能正常移动。
3. 玩家不会穿墙。
4. 氧气会正常变化。
5. 资源能正常采集。
6. 返航结算正常。
7. 金币和升级数据不乱。

## 15. 阶段卡住时的排查顺序

如果某阶段出现问题，优先按下面顺序排查：

1. 输入是否正常
2. 更新循环是否正常
3. 数据是否正确写入对象
4. UI 是否只是不显示，但数据已经变了
5. 场景切换时状态是否丢失

## 16. 最后结论

这个项目的正确推进方式不是“想到什么做什么”，而是：

1. 先保证一条主线闭环成立。
2. 再给闭环叠加风险和成长。
3. 最后再补完成度和展示材料。

只要按这个执行文档推进，每一个阶段都能独立验证，最终更容易做出稳定成品。
