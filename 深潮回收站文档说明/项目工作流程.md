# 项目工作流程

本文档把《深潮回收站》的开发顺序固定下来，确保整个项目始终围绕参考方案中的核心循环推进，而不是在功能堆积中失去主线。

## 工作流总原则

- 先做能跑，再做能玩，再做更好玩，最后做更好展示。
- 每一阶段都要有进入条件、退出条件、产物清单和回归要求。
- 任何想新增的功能，都必须先回答它服务哪个阶段目标。
- 如果某阶段没有通过标准，就不应靠增加新功能掩盖旧问题。
- 文档更新要跟着实现更新，而不是项目收尾时一次性补写。

## 阶段推进主线

- P0 工程基础确认 的目标是：建立可编译、可启动、可刷新的 Qt 图形化工程，让后续所有系统都有稳定宿主。
- P1 玩家移动 的目标是：建立潜航员在水下移动的基础手感，让玩家真正能控制一个对象探索海域。
- P2 碰撞与边界 的目标是：建立海域边界和障碍规则，让玩家不能穿墙、不能越界，并开始形成路线选择。
- P3 氧气系统 的目标是：把时间压力和深度压力接入核心循环，迫使玩家在探索和返航之间做决策。
- P4 采集与背包 的目标是：建立资源对象、交互提示、采集耗时和容量限制，让海底探索真正产生回报。
- P5 返航结算 的目标是：把一次出航收束为清晰的回报结算，首次完成完整玩法闭环。
- P6 升级系统 的目标是：把收益转化为长期成长，使玩家下一次出航明显更强、更远、更稳。
- P7 危险单位与环境机制 的目标是：让玩家面对主动风险，形成规避、试探和路线选择，而不是纯采集流水线。
- P8 海域推进与解锁 的目标是：建立阶段目标和中长期动力，让玩家感到自己正在走向更深、更难、更值钱的区域。
- P9 完成度打磨 的目标是：补齐存档、图鉴、HUD、音效和交互一致性，把可玩原型提升到可演示成品。
- P10 提交物验证 的目标是：把代码、文档、视频、报告和仓库状态统一检查到可提交水平，避免最后阶段低级失误。

## 统一执行模板

- 开始前先确认依赖阶段是否稳定。
- 实现前先写出本阶段目标、核心对象和最小演示结果。
- 实现中先打通主路径，再补异常处理和表现层。
- 阶段末必须做自测和回归，并把结论写回文档。
- 只有通过自测后，才允许扩展下一阶段。

说明：这类做法通常会让 工程基础确认 的问题在后面阶段放大，而不是被解决。

说明：这类做法通常会让 工程基础确认 的问题在后面阶段放大，而不是被解决。

### 阶段退出标准

- 连续启动程序 5 次，确认不会随机崩溃。
- 切换窗口焦点后再次返回，确认定时器和重绘不失效。
- 按下多个按键，确认输入事件确实被捕获。
- 断开一个无关资源路径，确认日志会给出可读错误。
- 把窗口最小化后恢复，确认场景仍能正常刷新。
