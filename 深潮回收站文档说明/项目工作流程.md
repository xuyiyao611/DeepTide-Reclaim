# 项目工作流程

## 1. 文档定位

本文档用于把 `深潮回收站` 项目的完整开发过程整理成一条稳定的推进主线。

目标不是一开始把全部功能同时做完，而是：

1. 先建立最小可运行原型。
2. 再形成“下潜 - 采集 - 返航 - 结算 - 升级”的完整闭环。
3. 最后补海域推进、危险机制、存档、打磨和视频展示内容。

如果后续推进中出现不确定，应优先回到本文件确认当前阶段，而不是随意并行扩功能。

## 2. 项目正式目标

本项目的正式目标固定为：

1. 使用 `C++` 完成一个图形化 2D 游戏。
2. 完成一个原创表达的“海底采集 + 氧气限制 + 返航出售 + 升级下潜”游戏原型。
3. 构建至少一个完整可玩的核心循环。
4. 具备清晰的模块划分、可测试性和可演示性。
5. 最终能够支撑实验报告、仓库迭代记录和 5 到 8 分钟讲解视频。

## 3. 当前推荐工作主线

项目后续推进不以“先把所有内容都做出来”为目标，而是按下面顺序推进：

1. 先把窗口、场景和玩家移动做稳定。
2. 再把氧气系统接入，让玩家有时间压力。
3. 再把资源对象和采集行为做出来。
4. 再实现返航和结算，形成第一条完整闭环。
5. 再做升级系统，让收益能转化为成长。
6. 再加入第二海域和危险单位，拉开中期玩法层次。
7. 最后补齐 UI、存档、图鉴、音效和视频展示准备。

这样推进的原因很明确：

- 玩家移动稳定，后续所有系统才有依附对象。
- 氧气系统决定了游戏的核心节奏。
- 没有采集系统，就无法体现主题。
- 没有返航结算，就没有完整循环。
- 没有升级系统，重复游玩的动力不足。
- 海域和危险内容应该建立在闭环已经可玩的前提上。

## 4. 分阶段工作总览

| 阶段 | 名称 | 目标 | 输出结果 |
|---|---|---|---|
| P0 | 工程基础确认 | 工程可构建、可运行、可切场景 | 项目进入可开发状态 |
| P1 | 主场景与玩家移动 | 建立玩家控制和基础渲染 | 角色可在海域中移动 |
| P2 | 地图边界与碰撞 | 建立空间规则 | 玩家不能穿墙和越界 |
| P3 | 氧气系统接入 | 建立风险压力 | 玩家必须在有限氧气下行动 |
| P4 | 资源与采集交互 | 建立采集玩法 | 可拾取和采集资源 |
| P5 | 返航与结算闭环 | 完成核心循环 | 可下潜采集并返航结算 |
| P6 | 升级系统 | 建立成长反馈 | 收益可转化为属性提升 |
| P7 | 危险单位与环境机制 | 增加风险和博弈 | 游戏不再只是采集模拟 |
| P8 | 海域推进与解锁 | 构建中期目标 | 进入第二和第三海域 |
| P9 | 存档、图鉴与界面打磨 | 提升完成度 | 项目可稳定展示 |
| P10 | 提交物准备 | 面向报告、视频和仓库整理 | 可提交、可录制、可讲解 |

## 5. 各阶段详细工作

## P0 工程基础确认

### 目标

- 确认项目采用的图形化框架可以稳定运行。
- 确认窗口初始化、资源路径、定时器和输入机制可用。

### 要做的事

- 新建 `Qt Widgets` 工程。
- 配置资源目录和基础窗口尺寸。
- 确定主循环使用 `QTimer`。
- 验证键盘输入可以传递到游戏场景。

### 输出结果

- 程序可启动。
- 主窗口可显示。
- 可以进入一张空白测试场景。

## P1 主场景与玩家移动

### 目标

- 先建立玩家存在感和可视化反馈。

### 要做的事

- 创建 `GameScene`。
- 创建 `Player` 类。
- 接入上下左右移动。
- 绘制玩家精灵或占位色块。

### 输出结果

- 玩家可以在场景中稳定移动。
- 帧更新和按键响应正常。

## P2 地图边界与碰撞

### 目标

- 建立海域边界、障碍和空间限制。

### 要做的事

- 确定地图坐标系。
- 增加岩壁、障碍区和海面边界。
- 实现 AABB 碰撞检测。
- 让玩家被碰撞盒限制。

### 输出结果

- 玩家不能穿墙。
- 玩家不能移出地图。

## P3 氧气系统接入

### 目标

- 给游戏加入时间和风险约束。

### 要做的事

- 给玩家添加 `maxOxygen` 和 `oxygen`。
- 每帧按时间消耗氧气。
- 根据深度增加附加消耗。
- 加入低氧预警显示。

### 输出结果

- 玩家如果探索过久会被迫返航。
- UI 上能明确看见风险变化。

## P4 资源与采集交互

### 目标

- 建立采集行为和背包逻辑。

### 要做的事

- 创建 `ResourceItem` 类。
- 实现漂浮资源和附着资源两类。
- 加入交互提示和采集进度。
- 接入背包容量判断。

### 输出结果

- 资源可采集。
- 背包状态可见。

## P5 返航与结算闭环

### 目标

- 把项目从“可移动原型”推进为“完整循环游戏”。

### 要做的事

- 定义海面安全区或返航点。
- 判断返航成功。
- 统计本次采集内容。
- 进入结算界面并转换为金币。

### 输出结果

- 项目首次形成完整循环。
- 玩家能明确感受到风险和收益。

## P6 升级系统

### 目标

- 给循环增加长期成长动力。

### 要做的事

- 创建基地场景或升级面板。
- 设计压缩气瓶、推进器、货舱、机械臂等升级项。
- 实现升级花费、等级上限和效果应用。

### 输出结果

- 玩家返航后有明确的下一步动机。
- 再次出航时能感知性能变化。

## P7 危险单位与环境机制

### 目标

- 让游戏出现博弈和路线选择，不只是重复采集。

### 要做的事

- 加入至少 1 种巡逻危险生物。
- 加入至少 1 种危险地形，例如热泉喷口。
- 加入受击、失控、扣耐久或扣氧气机制。

### 输出结果

- 玩家必须观察环境并调整路线。

## P8 海域推进与解锁

### 目标

- 形成中期目标和阶段成长感。

### 要做的事

- 制作第二海域。
- 设置海域解锁条件。
- 区分不同海域的资源、危险和视觉表现。

### 输出结果

- 玩家不会一直在同一地图重复刷资源。

## P9 存档、图鉴与界面打磨

### 目标

- 补齐完整度，提升演示效果。

### 要做的事

- 增加存档读取。
- 增加简单图鉴。
- 补齐开始菜单、结算界面和升级界面。
- 添加基础音效和动画反馈。

### 输出结果

- 项目进入“可以稳定展示”的阶段。

## P10 提交物准备

### 目标

- 面向大作业提交要求做最终包装。

### 要做的事

- 整理仓库目录。
- 完成 README。
- 准备实验报告结构。
- 准备视频脚本和演示顺序。
- 录制最终讲解视频。

### 输出结果

- 代码、文档、视频、报告都具备交付基础。

## 6. 每阶段推进原则

每个阶段都必须遵守：

1. 先做最小功能，不追求一次做满。
2. 当前阶段通过测试后，再进入下一阶段。
3. 每次新增系统后，必须回归验证前一阶段功能没有被破坏。
4. 每完成一个明显节点就提交一次仓库。

## 7. 推荐提交节点

建议至少按以下节点提交：

1. `v0.1` 工程和基础场景建立
2. `v0.2` 玩家移动与碰撞完成
3. `v0.3` 氧气和采集完成
4. `v0.4` 返航结算闭环完成
5. `v0.5` 升级和第二海域完成
6. `v1.0` 完成打磨、文档和视频准备

## 8. 当前最优先工作

如果当前项目还没有代码，最优先顺序永远是：

1. 能启动
2. 能移动
3. 能消耗氧气
4. 能采集
5. 能返航结算

这 5 项完成后，再考虑升级、敌人、图鉴、音效和视觉优化。
